# Zybo Z7-20 — the first board of the port

Digilent Zybo Z7-20: XC7Z020-1 (`xc7z020clg400-1`), 1 GB DDR3, armhf Linux, console on UART1, HDMI TX/RX through
SelectIO TMDS (no HDMI chips), SSM2603 audio codec, USB host (PS USB0), SD card on PS SD0. Board files and master XDC
come from Digilent (MIT license, see `LICENSES/README.md`).

| Path | Content |
|---|---|
| `platform.mk` | board profile: flows `vivado kernel uboot boot rootfs mister`, setup checkouts, `VIDEO_TX` (dvi/hdmi), boot design `zybo-z7-20_msx[_hdmi]`, `MISTER_CORES` |
| `board_files/`, `constraints/` | Digilent board files (1.1), master XDC (pin reference), `zybo-z7-20_mister.xdc` (pins and clock groups of every MiSTer design) |
| `scripts/2025.2/` | `zybo-z7-20_mister.tcl`: block design and generator of every MiSTer design (`CORE=<core>`, `VIDEO=dvi|hdmi`) |
| `files/mister-rootfs/` | `ssm2603-init.sh` + `ssm2603.service` (codec setup over I2C0 at boot) |
| `dts/zynq-zybo-z7.dts` | kernel/U-Boot DTS; reserves 0x1FF0_0000-0x3FFF_FFFF for the PL and Main_MiSTer |
| `files/` | `uEnv.txt` (boot menu SD, TFTP/NFS), `uboot.config`, `kernel.config` (input, HID PlayStation, Bluetooth) |

Designs: `zybo-z7-20_<core>` (DVI through `rgb2dvi`) and `zybo-z7-20_<core>_hdmi` (HDMI with sound through
`hdmi_out` of `firmware/common/ip/hdmi-tx`) for every core profile (menu, msx, snes, psx, n64), all generated by `zybo-z7-20_mister.tcl`
(`PLATFORM=zybo-z7-20 FLOW=vivado CORE=snes VIDEO=hdmi make create build`). The XC7Z020 is too small for the full
SNES, PSX and N64 cores: their profiles leave out options (core `README.md` files), and N64 runs at its original
clocks outside its timing constraints. `MISTER_CORES` packages all of them: menu, MSX (`_Computer`), SNES, PSX and
N64 (`_Console`).

Hardware setup: jumper JP5 on SD (boot from the SD card), jumper JP2 (HOST) must be set for USB host mode, otherwise the OTG connector gets no VBUS and no
USB device (keyboard, Bluetooth adapter) enumerates. Keyboard through an OTG adapter on the USB port works.
There is one USB port: keyboard and Bluetooth adapter at the same time need a USB hub.

Bluetooth (DualSense/DualShock 4): the Ubuntu rootfs uses the system `bluetoothd` (bluez 5.72, `bluetooth.service`)
and the kernel HIDP path with `hid-playstation`; Main_MiSTer's own Bluetooth helpers (`/bin/bluetoothd`, MiSTer image
convention) do not exist here (journal: `/bin/bluetoothd: not found`). Pair from a shell on the board:
`firmware/common/mister/tools/pair-ds5.sh` (copy to the board; controller in pairing mode with Create + PS), it trusts,
pairs and connects. Main_MiSTer takes the new `/dev/input/event*` without restart; afterwards the controller
reconnects with the PS button. The Bluetooth modules (`bluetooth`, `btusb`, `hidp`) come with the kernel package of
the build that enabled them (`files/kernel.config`). Checked 2026-10-31 with a CSR 0a12:0001 adapter (BT 2.1, no
firmware file; one `hardware error 0x37` at setup) and a DualSense: paired, connected, Main opened the gamepad, playing a
PSX game works.

Pitfalls: 1080p runs the SelectIO TMDS beyond the XC7Z020-1 datasheet (720p is within it); the FSBL
is built on demand from the XSA of the boot design (`files/fsbl/` is not tracked here). U-Boot sets no board MAC
address: every Zybo with this image uses the Xilinx default `00:0a:35:00:00:00` and gets the same DHCP lease, so
only one such board works in a network at a time (open: the unique MAC in the OTP area of the QSPI flash).
